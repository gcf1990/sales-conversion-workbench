# 销售转化工作台前端设计文档

日期：2026-06-10  
状态：前端 Demo 评审后更新版

## 1. 页面定位

本项目是全新的“销售转化工作台”，不复用旧六量七率工作台的标签体系、脚本、页面结构或数据结构。

第一阶段定位是“经营诊断汇报页”，不是营销页，也不是自由探索型 BI。页面要帮助业务快速完成：

```text
先看当前范围的核心结论 -> 定位优先处理门店 -> 进入门店三层诊断 -> 查看问题证据和动作建议
```

前端原则：

- 结论先行，默认告诉业务当前最应该处理什么。
- 表格和筛选优先，不做大面积装饰。
- 页面采用上下结构，不做左右并行主布局。
- 默认展示管理动作需要的信息，复杂口径、模型细节和附录信息弱化。
- Demo 阶段使用样例数据，前端确认后再接入真实观远指标、IP 电话文本和试驾录音文本。

## 2. 用户身份与口径

页面需要适配不同身份进入：

- 全国总部
- 大区
- 小区
- 经销商/门店

因此页面文案不能固定写成“本小区”“大区均值”“本门店”。统一使用：

| 场景 | 推荐文案 |
|---|---|
| 当前筛选范围的加总值 | 当前 |
| 当前范围的单店表现 | 单店 |
| 可比门店平均值 | 均值 |
| 可比门店平均单店量 | 均值/店 |

指标卡上不展示“当前”字样作为独立标签，第一行直接用“指标名称 + 当前值”表达。

## 3. 页面主线

页面主线固定为：

1. 顶部筛选：选择日期、品牌、车系、区域、问题类型。
2. 当前结论：说明当前范围最严重问题、问题门店数量、预计影响规模和建议优先动作。
3. 第一层漏斗：展示下发线索、首触到店、首触试驾、首触订单。
4. 问题门店清单：按优先级和影响规模排序，帮助业务先处理重点门店。
5. 门店三层诊断：点击门店后进入核心指标、过程指标、问题诊断。
6. 明细证据：仅在 IP 电话和试驾模块下展示具体顾问和文本证据。

## 4. 首屏信息

首屏需要放：

- 页面标题：销售转化工作台。
- 全局筛选：日期、品牌、车系、区域、问题类型。
- 当前结论：当前范围最严重问题、P1/P2 问题门店数量、预计影响订单、优先处理门店和动作。
- 第一层漏斗指标卡。
- 问题优先处理门店清单前几行。

首屏不放：

- 详细打标口径。
- 明细证据列表。
- 模型解释、脚本说明、数据校验过程。
- 过多装饰性图形。

## 5. 第一层：销售转化漏斗

第一层保留四个核心环节：

```text
下发线索 -> 首触到店 -> 首触试驾 -> 首触订单
```

后续真实数据字段对齐：

| 页面指标 | 观远字段 | 口径 |
|---|---|---|
| 下发线索 | `today_down_sign_leads_cnt` | 下发线索数 |
| 首触到店 | `today_fst_touch_pflow_cnt` | 首触到店 |
| 首触试驾 | `today_fst_touch_trial_cnt` | 首触试驾 |
| 首触订单 | `today_fst_touch_order_cnt` | 首触订单 |

后续可接入的第一层漏斗数据集：

- 数据集名称：`[缓存][三品牌]新零售门店级每日全量指标宽表&ads_sale_mart_new_sale_store_lvl_day_exnorm_comb_wms_his`
- 数据集 ID：`e477e5d5aa4664fadb3a7ec7`

### 5.1 指标卡展示规则

每张指标卡第一行直接展示“指标名称 + 指标值”，名称和值保持同一层级的加粗大字。

示例：

```text
下发线索  1,684
单店线索 337
均值/店 357
```

卡片补充信息：

| 指标卡 | 补充字段 |
|---|---|
| 下发线索 | 单店线索、均值/店 |
| 首触到店 | 线索到店率、均值 |
| 首触试驾 | 到店试驾率、均值 |
| 首触订单 | 目标达成率、试驾订单率、均值达成 |

首触订单卡的展示顺序：

```text
首触订单 34
目标达成率 36.2%
试驾订单率 17.1%
均值达成 35.0%
```

若目标达成率低于时间进度，只高亮“目标达成率”标签，不高亮整张卡片。

## 6. 问题门店清单

首页门店清单不使用讲不清的“严重度分值”或黑箱综合评分。

排序规则采用可解释优先级：

```text
问题优先级 P1/P2/P3 -> 命中异常指标数量 -> 预计影响规模
```

主表字段：

| 字段 | 说明 |
|---|---|
| 门店 | 门店简称 + 所属区域 |
| 问题优先级 | P1/P2/P3 |
| 门店问题类型 | 例如双断点门店、邀约断点门店、转化断点门店 |
| 命中异常指标 | 线索到店率低、30s 以下线索占比高、试驾订单率低等 |
| 线索到店率 | 邀约阶段转化表现 |
| 30s 以下占比 | 短通话异常信号 |
| 试驾订单率 | 试驾后订单转化表现 |
| 影响规模 | 预计影响订单数 |
| 操作 | 查看诊断 |

## 7. 门店诊断三层结构

点击“查看诊断”后进入门店三层分析。

### 7.1 门店诊断概览

门店诊断顶部展示：

- 门店名称。
- 问题优先级。
- 门店问题类型。
- 预计影响规模。

不再展示右上角“邀约阶段/转化阶段”徽标，避免和下方可点击过程指标重复。

### 7.2 第一层：核心环节

第一层展示该门店的四个核心环节：

```text
下发线索 / 首触到店 / 首触试驾 / 首触订单
```

每张卡展示门店值和均值对比，帮助判断该门店在同类门店中的位置。

### 7.3 第二层：关键过程指标

第二层保留三个关键过程指标：

| 第二层指标 | 业务含义 | 第三层联动 |
|---|---|---|
| 30s 以下线索占比 | 短通话线索主要来自哪些渠道 | 分渠道 30s 以下线索占比 |
| 线索到店率 | IP 电话是否有效完成邀约 | IP 电话邀约问题 |
| 试驾订单率 | 试驾接待是否有效转订单 | 试驾接待问题 |

## 8. 第三层：问题诊断联动

第三层必须根据第二层点击指标切换，不同指标的下钻深度不同。

| 当前点击指标 | 第三层内容 | 顾问排行 | 明细证据 |
|---|---|---|---|
| 30s 以下线索占比 | 渠道大类短通话占比，可展开二级渠道 | 不展示 | 不展示 |
| 线索到店率 | IP 电话邀约问题分布、顾问问题排行 | 展示 | 展示 |
| 试驾订单率 | 试驾接待问题分布、顾问问题排行 | 展示 | 展示 |

### 8.1 30s 以下线索占比

该指标只用于定位短通话线索主要来自哪些渠道，不直接联动 IP 电话邀约问题。

展示内容：

- 渠道大类条形图。
- 每个渠道展示短通话线索数、总线索数、短通话占比。
- 渠道大类支持展开二级渠道。
- 不展示顾问排行。
- 不展示明细证据区。

### 8.2 IP 电话邀约问题

点击“线索到店率”后展示。

展示内容：

- 6 类问题分布。
- 每类问题的命中明细数和占比。
- 每类问题下的自然语言概括，说明该门店具体差在哪。
- 顾问问题排行，条形图展示绝对值。
- IP 电话文本明细证据。

### 8.3 试驾接待问题

点击“试驾订单率”后展示。

展示内容：

- 6 类问题分布。
- 每类问题的命中明细数和占比。
- 每类问题下的自然语言概括，说明该门店试驾接待中具体差在哪。
- 顾问问题排行，条形图展示绝对值。
- 试驾录音文本明细证据。

## 9. 问题类型体系

IP 电话和试驾接待共用同一套一级问题类型，只是数据来源不同。

| 一级问题类型 | 核心定义 |
|---|---|
| 客户需求识别不足 | 顾问没有先弄清客户真实购车动机、预算、用途、周期、决策人、对比车型，就开始介绍、报价或邀约 |
| 产品价值转化不足 | 顾问讲了功能、配置、参数，但没有讲清这些内容对客户有什么实际好处 |
| 版本价格推荐不清 | 客户问低配、中配、高配、优惠、落地、分期时，顾问没有帮客户判断哪个版本最适合 |
| 顾虑异议承接不足 | 客户表达担心、拒绝、犹豫、质疑时，顾问没有正面接住并化解 |
| 竞品对比引导不足 | 客户提到其他品牌、车型、网上评价时，顾问没有建立清晰对比逻辑 |
| 下一步推进锁定不足 | 顾问没有把当前沟通推进到明确下一步动作，导致客户热度流失 |

数据来源：

| 诊断对象 | 数据来源 |
|---|---|
| IP 电话邀约问题 | IP 电话文本 |
| 试驾接待问题 | 试驾录音文本 |

## 10. 二级问题与自然语言概括

后续真实打标需要在每个一级问题下继续解析二级问题，但前端不应只展示“二级标签 + 数字”。

推荐方式：

1. 后台保留二级标签和命中次数，用于统计和证据追溯。
2. 前端在一级问题条形图下，用自然语言概括该门店在该问题下的具体表现。
3. 自然语言概括需要落到业务可理解的场景，而不是简单复述指标。

Demo 预设二级标签方向：

| 一级问题 | 二级标签示例 | 前端概括方向 |
|---|---|---|
| 客户需求识别不足 | 购车动机、购车预算、购车用途、购车周期、决策人、对比车型 | 说明顾问主要没有问透哪些需求，是否过早进入报价或邀约 |
| 产品价值转化不足 | 配置讲解、用车场景、家庭出行、通勤成本、产品收益 | 说明卖点是否没有转成客户能感知的价值 |
| 版本价格推荐不清 | 版本差异、落地价、金融方案、置换政策、优惠解释 | 说明客户在价格和版本选择上卡在哪里 |
| 顾虑异议承接不足 | 价格顾虑、质量担忧、拒绝原因、竞品犹豫、售后顾虑 | 说明顾问是否接住并化解客户犹豫 |
| 竞品对比引导不足 | 竞品差异、网上评价、替代车型、品牌认知、对比逻辑 | 说明顾问是否建立了清晰的对比理由 |
| 下一步推进锁定不足 | 到店时间、试驾预约、资料补充、再联系时间、紧迫感 | 说明是否没有锁定下一步动作 |

## 11. 明细证据区

明细证据区只在 IP 电话和试驾接待模块展示。

一条明细可以命中多个问题类型。

建议字段：

| 字段 | 用法 |
|---|---|
| `issue_tags` | 多个命中问题类型 |
| `primary_issue` | 主问题类型，用于顾问排行和默认聚合 |
| `evidence_text` | 电话或试驾文本中的关键证据 |
| `advisor_name` | 顾问 |
| `customer_id` | 客户标识，Demo 可匿名 |
| `scenario` | `ip_call` 或 `test_drive` |
| `suggestion` | 改进建议 |

明细卡展示：

- 顾问。
- 客户标识。
- 沟通场景。
- 命中问题标签。
- 关键证据片段。
- 建议动作。

## 12. 筛选与交互

全局筛选：

- 日期
- 品牌
- 车系
- 区域
- 问题类型

关键交互：

- 点击门店清单“查看诊断”，切换门店诊断区域。
- 点击第二层过程指标，切换第三层诊断内容。
- 点击问题类型，可筛选右侧顾问排行和明细证据。
- 点击渠道大类展开按钮，展示二级渠道。
- 点击重置问题筛选，恢复默认问题分布。

## 13. 弱化或放附录的信息

以下信息不应进入首屏主叙事：

- LLM 打标 Prompt。
- 二级标签完整枚举。
- 明细级字段口径。
- 数据校验日志。
- 指标复算脚本。
- 模型置信度和内部阈值。
- 复杂评分公式。

如后续需要，可放到附录、数据说明页或开发文档。

## 14. 当前 Demo 验收标准

前端 Demo 需要满足：

1. 进入页面后能先看到当前范围的经营结论。
2. 漏斗指标卡能清楚展示当前加总值和均值对比。
3. 首触订单卡能展示目标达成率，低于时间进度时只高亮目标达成率标签。
4. 问题门店清单不出现黑箱严重度分值。
5. 门店诊断是上下结构，页面不拥挤、不错位。
6. `30s 以下线索占比` 只下钻到渠道大类和二级渠道，不展示顾问排行和明细证据。
7. `线索到店率` 联动 IP 电话邀约问题。
8. `试驾订单率` 联动试驾接待问题。
9. IP 电话和试驾模块都展示 6 类问题分布、自然语言概括、顾问排行和明细证据。
10. 页面用语能同时适配总部、大区、小区和门店身份。
